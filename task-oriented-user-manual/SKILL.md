# Task-Oriented User Manual

Create a manual in which a first-time user can **orient, act, confirm, and recover** through visible interface cues and user goals.

## Method

### 1. Model the work

Identify the audience, user roles, intended outcomes, in-scope tasks, visible interface evidence, and source material. Build a **task architecture** around user goals rather than product components. Create separate manuals only when roles have materially different responsibilities.

Completion criterion: every in-scope user goal belongs to one role and one task; role boundaries and source gaps are explicit.

### 2. Design the publication spine

Use this sequence unless the source or requested format requires a justified variation:

1. Cover
2. Table of contents
3. Introduction
4. Get started
5. Task chapters
6. Troubleshooting
7. Glossary

Apply **progressive disclosure**: orient before instructing, introduce prerequisites before tasks, and place specialist detail only where the user needs it. Begin each task on a new page; the introduction may flow into Get Started.

Completion criterion: the reading order supports first use, routine use, and recovery without duplication.

### 3. Write task loops

Give each task a clear action-led title and this compact anatomy:

- **Purpose**: the outcome and when it is relevant
- **Location**: the navigation path using exact visible labels
- **Procedure**: one observable action per numbered step
- **Confirmation**: the visible evidence of success
- **Recovery**: the most likely user-facing check when the task fails
- **Figure**: only when it materially reduces ambiguity

Use direct verbs, plain professional language, and the reader's vocabulary. Preserve **interaction fidelity**: UI labels, sequence, states, and outcomes must match the product evidence. Emphasize the action or label that controls the next decision.

Completion criterion: each task independently answers where to go, what to do, how success appears, and how to recover.

### 4. Apply visual economy

Use screenshots as navigation evidence. Crop to the relevant context and keep text legible. Reserve red-box callouts for ambiguous navigation, visually weak controls, and critical or final actions; let obvious fields, static information, and routine steps remain visually quiet.

Use stable, descriptive Markdown image paths and keep every figure reference adjacent to the action it clarifies.

Completion criterion: every visual removes a plausible point of confusion, every callout has a decision-making purpose, and every image reference resolves.

### 5. Assure the publication

Remove retired, duplicate, role-irrelevant, and implementation-level material. Keep troubleshooting symptom-led and actionable; define unavoidable product terms in the glossary.

Render the deliverable and inspect the final PDF for:

- task and role coverage
- interface accuracy
- readable typography and images
- intentional page breaks and pagination
- coherent contents and cross-references
- valid links and image paths

Completion criterion: a first-time user can complete every documented task from the rendered manual, and all checks pass or are reported as explicit source gaps.
